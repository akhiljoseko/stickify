Label Grid is an enterprise-grade industrial label printing application built in Flutter. It empowers logistics managers and warehouse operators to visually design custom sticker templates, bind them dynamically to product metrics, layout items across print sheets with millimeter accuracy, and spool them directly to local system printers.

Designed with offline-first persistence, local driver corrections for Windows printers, and remote syncing capabilities, Label Grid is engineered for modern logistics pipelines.

---

## Architecture & Design Patterns

The project follows a decoupled **Clean Architecture** combined with a modular presentation design:

1. **Domain Layer (`lib/domain/`)**: Holds pure business logic, entities (`Product`, `LabelTemplate`), and abstract repository/service interfaces (`PrintService`, `FileStorageService`). It has zero external dependencies.
2. **Data Layer (`lib/data/`)**: Implements abstract contracts. Contains local storage implementations (`HiveLocalDatabase` using Hive CE), remote connections (`FirestoreProductRepository`), syncing queues, and local OS-specific file manipulation.
3. **Presentation Layer (`lib/presentation/`)**: Modularized by functional feature area (e.g. `product`, `template_editor`, `print`, `dashboard`), separating dependency injection (`Page`) from visual representation (`View`) and utilizing `flutter_bloc` for state management.
4. **Dependency Injection**: Orchestrated manually via `AppServiceLocator` (`lib/app/app_service_locator.dart`), bypassing third-party DI packages to maintain clean compile-time safety.
5. **Routing System**: Driven by `go_router` and type-safe `@TypedGoRoute` schemas generated by `build_runner`.

## Getting Started 🚀

This project supports three target configuration flavors:

- **development**
- **staging**
- **production**

To launch the application from the CLI, execute:

```sh
# Development (Targeting Windows default)
$ flutter run --flavor development --target lib/main_development.dart

# Staging
$ flutter run --flavor staging --target lib/main_staging.dart

# Production
$ flutter run --flavor production --target lib/main_production.dart
```

## Essential Commands 🧪

### Running Tests
To run the automated unit and widget test suites with randomize seed scheduling:
```sh
$ very_good test --coverage --test-randomize-ordering-seed random
```

To review test coverage metrics locally:
```sh
# Generate HTML coverage pages
$ genhtml coverage/lcov.info -o coverage/

# Open report in browser
$ open coverage/index.html
```

### Static Analysis & Lints
Validate style rules using the project analyzer configuration:
```sh
$ flutter analyze
```

Check specialized BLoC architectural rules:
```sh
$ dart run bloc_tools:bloc lint .
```

### Code Generation
Regenerate routing configurations, Hive models, and serializations:
```sh
$ dart run build_runner build --delete-conflicting-outputs
```

## Localization & Internationalization 🌐

Label Grid uses standard ARB template translations managed under `lib/l10n/arb/`.

To manually compile local translations:
```sh
$ flutter gen-l10n --arb-dir="lib/l10n/arb"
```

Otherwise, translation compilation runs automatically during standard `flutter run` triggers.
